--------------------------------------------------------------------------------
  2. HOW FAILURES GET FIXED
--------------------------------------------------------------------------------

   Every command that can fail is repaired automatically:

     1. the bot runs the command
     2. if it exits non-zero, opencode is shown the command, the exit code and
        the output, and is asked for the corrected command
     3. the bot runs the corrected command
     4. up to OPENCODE_FIX_ATTEMPTS times (default 3)

   The repair keeps the original intent: only the technical problem is fixed
   (wrong flag, wrong tool name, wrong syntax, missing permission).

   If nothing can be repaired, opencode explains what went wrong and the bot
   runs the closest working alternative, so you still get an answer.

   Examples:
     !sh ls --colour=always /etc/hostname
       -> fails, opencode changes it to --color=always, bot runs it, you get
          the file listing
     !sh ls -la /no/such/dir
       -> fails, cannot be repaired, opencode explains why, and the bot lists
          the working directory instead

  3. DAILY HABIT CHECK-IN  [everyone]
--------------------------------------------------------------------------------

  Automatic, 8:00 PM every day:
    - habits are posted ONE AT A TIME as plain messages
    - answer the current one with `done`, `in progress`, `pending` or `missed`
    - no answer after 5 min -> a reminder
    - no answer after 10 min -> it moves on (late answers still count)

  ANSWERING (no "!" needed):
        done               record the current habit as done
        in progress        record it as started, not finished
        pending            record it as not started (clears a previous answer)
        missed             record the current habit as missed
        Done / DONE / yes / haan      all count as done
        Missed / no / nahi            all count as missed
        started / doing / wip          count as in progress
        not yet / later                count as pending
        ✅ / ❌ / 👍 / 👎 / 🔄 / ⏳    also work

  COMMANDS
  !mission                        Your check-in status for today.
        !mission

  !mission status                 Same as !mission.
        !mission status

  !mission done <habit>           Mark a habit done.
        !mission done 5L Water
        !mission done upsc
        !mission done gym

  !mission in_progress <habit>    Mark a habit started but not finished.
        !mission in_progress 5L Water

  !mission pending <habit>        Clear a habit back to "not started".
        !mission pending upsc

  !mission missed <habit>         Mark a habit missed.
        !mission missed sleep
        !mission missed wake

  !mission habits                 List today's habits and their keys.
        !mission habits

  NOTE: matching is fuzzy — "5l water", "water", "5L" all resolve.
  Whenever `!mission done <habit>` matches the habit currently pending in the
  chain, the chain advances to the next habit.

--------------------------------------------------------------------------------
  6. SAFETY REMINDERS
--------------------------------------------------------------------------------

  - Everything in section 1 is OWNER-ONLY. Add ids to MISSION_OWNERS to change
    who that is; `!whoami` tells you your own id.
  - There are no confirmation prompts — the bot runs the command immediately.
  - Every control command is appended to control_audit.log with the sender id
    and a UTC timestamp.
  - Set MISSION_CONTROL_DRY_RUN=1 to log commands without executing them.
  - `!sh` is the most powerful command. `!lock` and `!screen` are safe;
    `!sh`, `!close` and `!type` are not.
  - If a command fails for any reason, you always get a "⚠️ ..." reply saying
    what went wrong, and opencode gets a shot at repairing it first. Failures
    are never silent, and a failed check-in save tells you it is queued for
    retry instead of pretending it worked.
  - `!task` needs the opencode CLI on the bot's PATH and a working opencode
    service, plus a "planner" agent with no shell (see README).
